# حفرة! — نسخة Expo (بناء سحابي، بدون Android Studio)

اللعبة (`assets/hofra.html`) مغلّفة داخل WebView بسيط. كل الصور والأصوات مضمّنة داخل ملف اللعبة نفسه (base64)، فما فيه أي اعتماد على إنترنت وقت التشغيل.

---

## خطوات البناء

```bash
cd hofra-expo-project

# 1) تثبيت الحزم — استخدم هذا بدل npm install العادي
#    عشان يجيب نسخ متوافقة بالضبط مع إصدار Expo SDK الحالي
npx expo install

# 2) تسجيل دخول Expo (حساب مجاني)
npx eas-cli login

# 3) بناء تجريبي (APK تقدر تركّبه على جوالك مباشرة وتجرب)
npx eas-cli build --platform android --profile preview

# 4) لما يعجبك، ابني النسخة النهائية لجوجل بلاي (AAB موقّع تلقائياً)
npx eas-cli build --platform android --profile production
```

الأمر الأخير يرفع المشروع لسيرفرات Expo، يبنيه هناك، ويديك رابط تحميل لملف `.aab` جاهز يترفع مباشرة على Play Console. ما تحتاج Android Studio ولا Java ولا Gradle على جهازك إطلاقاً.

أول مرة تسوي build، EAS راح يسألك تسوي Keystore — خليه يسويه تلقائياً ويخزنه على حسابك (أسهل وأأمن من إدارته يدوياً).

---

## نفس النقاط المهمة قبل الرفع الفعلي (ذكرتها قبل، تنطبق هنا كمان)
1. أزرار "شاهد إعلان" الوهمية — لازم AdMob حقيقي (فيه حزمة `react-native-google-mobile-ads` تتوافق مع Expo) أو تشيل الميكانيكية قبل الرفع.
2. سياسة خصوصية إلزامية لأي تطبيق على Play Console.
3. مستوى الـ API المستهدف — Expo يتكفل بيه تلقائياً لأنه يحدّث القيم الافتراضية مع كل إصدار SDK جديد، ما تحتاج تتابعه يدوياً زي مشروع Capacitor.

## ملاحظة تقنية واحدة
تأكد بعد ما تبني وتجرب النسخة إن حفظ النتيجة/العملات شغّال صح (localStorage جوّه الـ WebView) — الإعداد `domStorageEnabled` مفعّل في `App.js` أصلاً وهو المسؤول عن كذا، بس دايماً زين تتأكد بتجربة حقيقية بعد أول تركيب على جهاز حقيقي.
